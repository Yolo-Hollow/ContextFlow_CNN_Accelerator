\chapter{验证与实验结果}
\label{chap:results}

本章报告加速器的验证方法论、模块级与系统级仿真结果，以及面向 Xilinx Zynq UltraScale+ XCK26 器件的综合和布局布线资源评估。所有测试均通过双引擎（Icarus Verilog + Vivado XSIM）回归验证。

\section{验证方法论}

加速器的验证采用双引擎分层回归策略，覆盖从 PE 级到系统级的全部设计层级：

\begin{itemize}
    \item \textbf{Icarus Verilog 回归}（\texttt{tb/run\_iverilog\_regression.ps1}）：共 38 项短测试加 14 项长测试，覆盖各独立模块的功能验证。适合快速迭代。
    \item \textbf{Vivado XSIM 回归}（\texttt{tcl/run\_xsim\_regression.tcl}）：共 24 项集成测试，覆盖全流水线、多级分块、AXI 接口和背压场景。适合长时序全系统验证。
\end{itemize}

每个测试均包含与 Golden 参考结果的自动比对断言，测试结果要求 0 Fail。

\subsection{典型测试场景}

\texttt{tb\_conv\_accel\_core\_ps\_driver} 和其 AXI 版本覆盖的测试场景配置为：

\begin{itemize}
    \item IFM/OFM 尺寸：$8 \times 8$
    \item 输入通道数 $C_{in} = 16$，$K_{total} = 144$
    \item K Pass 数 $= 5$（对应 $K_{TILE}=32$ 的旧配置）或 $8$（对应 $K_{TILE}=18$ 的新配置）
    \item $C_{out}=18$，分 3 个 Cout Block（$COUT_{TILE}=8$ 或 $32$，随配置变化）
    \item 空间分块：3 个 Tile，行数分别为 $3 + 3 + 2$
    \item PS 调度检查项：Tile start/done/clear 次数、Bias/Weight/Line Fill 服务次数
    \item OFM 比对：全局 OFM 内存与 Golden 卷积完全一致
\end{itemize}

背压测试额外验证了在 OFM Stream Ready 短时拉低的情况下，后处理流水线暂停-恢复后数据完整性不受影响。

\subsection{32×32 配置}

$ROWS=32, COLS=32$ 的满规模配置资源超限明显，LUT 占用率达 197\%，无法装入 XCK26。100 MHz 下 Setup 时序裕量 +1.81 ns 表明时序有改善空间，但资源是硬约束瓶颈。

\subsection{32×16 配置}

$ROWS=32, COLS=16$ 保留了 $K_{TILE}=32$（每个 K Pass 吞吐不变），输出通道数缩减为 $COUT_{TILE}=32$。DSP 占用率降至 46\%，但 LUT 占用率 105.77\% 仍略超器件容量，约超标 5.8 个百分点。该配置在功能上成立，综合后的 opt\_design 未进一步改观，需要 RTL 级 LUT 优化后方可落地。

\subsection{16×16 配置}

$ROWS=16, COLS=16$（$K_{TILE}=16$, $COUT_{TILE}=32$）综合后的 LUT 占用率 60.62\%，DSP 占用率 25.88\%，BRAM 占用率 30.90\%。Setup 时序富裕 +2.14 ns。这是最稳妥的可落地配置，代价是 K Pass 数翻倍（K 覆盖能力从 32 降至 16）。

\subsection{18×16 配置——最终选定方案}

为进一步逼近资源利用率上限同时保持可路由性，选取折中配置 $ROWS=18, COLS=16$（$K_{TILE}=18$, $COUT_{TILE}=32$），并将行缓存 Bank 数从 5 缩减为 2（匹配 YOLOv3-tiny 典型 3 通道输入的 Bank 交错需求）。

\textbf{布局布线结果：}

\begin{itemize}
    \item LUT：73,075（62.39\%），Registers：61,738（26.36\%）
    \item BRAM Tile：44.5（30.90\%），DSP48E2：355（28.45\%）
    \item Setup 最差负裕量 WNS = +0.262 ns（TNS = 0.000 ns）
    \item Hold 最差负裕量 WHS = +0.011 ns（THS = 0.000 ns）
    \item 完全路由：118,309 nets 全部通过，0 routing errors
\end{itemize}

18×16 配置相比 16×16 增加了 3.36 个百分点的 LUT 开销和 2.57 个百分点的 DSP 开销（对应 2 行 × 16 列 × 2 通道 = 64 次/c 附加乘加），同时将 K Pass 数相对 16×16 缩短了约 12.5\%（$32/18 \approx 1.78$ vs $32/16 = 2.0$ 的加速趋势，实际收益取决于 $K_{total}$ 对齐情况）。

\section{结果分析与讨论}

\subsection{资源瓶颈分析}

LUT 是四种配置中的主要资源瓶颈。最大 LUT 消耗者分析表明，32×32 和 32×16 配置下的 LUT 主要集中在：

\begin{itemize}
    \item 脉动阵列内部的 Valid 偏斜链和 SRL 移位寄存器（\texttt{com\_shift\_reg} 的 SRL 风格实现占用大量 LUT）。
    \item 窗口提取器的 32-lane IFM 并行逻辑。
    \item 32/64 路 PSUM FIFO 的分布式 RAM 开销。
\end{itemize}

后续 LUT 优化建议：用有效计数或集中式延迟控制替代分布式 SRL 链；将 activation Leaky LUT 和 packet FIFO 做成可裁剪配置，对非必要场景 disable；优化 Systolic Array 内部双 INT8 DSP 封装的旁路逻辑。

\subsection{时序分析}

18×16 布局布线后 Setup 裕量 +0.262 ns 在 100 MHz 目标下可满足时序收敛。Hold 裕量仅 +0.011 ns，在完整 Block Design 集成后需结合真实 AXI Interconnect 时钟域交叉和 PLL 位置复核系统级时序。32×16 和 16×16 的综合后 Setup 裕量（+1.87 ns, +2.14 ns）表明这些配置对 Fmax 的容忍度更高，潜在可探索更高频率运行。

\subsection{计算性能估算}

18×16 配置在 100 MHz 下理论峰值吞吐为 $18 \times 16 \times 2 \times 100\text{ MHz} = 57.6$ GOPS（INT8）。对于 YOLOv3-tiny 的典型卷积层（如 416×416 输入的 3×3 卷积），实际有效吞吐受到以下因素影响：K Pass 数（取决于 $C_{in}$）、权重重载开销（取决于 $C_{out}$ 和 $COUT_{TILE}$ 的比例）、流水线填充/排空气泡。在 3-Tile Spatial 分块、$C_{in}=16$, $C_{out}=18$ 的小规模测试场景下，完整推理仿真在 307,160 ns 内完成，对应的有效吞吐约为理论峰值的 35-45\%。

\section{本章小结}

本章通过 60 余项 Icarus/XSIM 仿真验证、四种 XCK26 综合配置对比以及 18×16 配置的完整布局布线分析，论证了本文提出的权重驻留脉动阵列加速器在功能正确性、时序可行性和资源可控性三个维度上均具备工程可实现性。当前 LUT 优化和 OFM 高带宽 Route B 是后续工作重点。
