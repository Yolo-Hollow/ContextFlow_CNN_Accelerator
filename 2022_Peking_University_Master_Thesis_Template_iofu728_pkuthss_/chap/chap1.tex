\chapter{绪论}

\section{研究背景与意义}

卷积神经网络（Convolutional Neural Network, CNN）已经成为目标检测、图像分类和语义理解等视觉任务的核心计算模型。YOLO 系列检测器将候选框生成和类别预测整合为单阶段推理流程，在边缘端实时感知任务中具有较好的工程适配性~\cite{redmon2016yolo,redmon2018yolov3}。其中 YOLOv3-tiny 通过减少层数和通道规模降低计算量，适合在嵌入式平台上部署。

边缘端部署面对的约束与数据中心不同。通用 CPU 的吞吐有限，嵌入式 GPU 或专用 NPU 虽然性能较高，但在功耗、可定制性、接口灵活性和可验证性方面并不总是满足定制系统需求。FPGA/MPSoC 平台同时包含处理系统（Processing System, PS）和可编程逻辑（Programmable Logic, PL），能够让软件负责图像输入、调度和后处理，让硬件承担规则密集的卷积计算。因此，基于 FPGA 的 CNN 加速器仍然是边缘智能系统中的重要研究方向~\cite{qiu2016going,guo2019angeleye}。

然而，真实 CNN 网络的端到端加速并不等同于构造一个高峰值 MAC 阵列。以 YOLOv3-tiny 单尺度链路为例，网络包含 3x3 卷积、1x1 卷积、池化、量化、激活和检测头；每一层还要经过输入通道展开、输出通道分块、空间 tile 分块和多轮 K pass 累加。若数据搬运、部分和反馈或 pass 边界调度处理不当，硬件阵列会在等待权重、等待 IFM replay、等待 partial-PSUM drain 或等待 DMA 完成时产生大量空泡。本文关注的核心问题正是：\textbf{如何在资源受限的 MPSoC 上，面向真实 YOLOv3-tiny 链式推理降低非计算开销，并使优化效果能够被板级实验和性能计数器解释。}

\section{国内外研究现状}

CNN 加速器的研究大致经历了从算子级流水线到空间阵列架构的发展。Kung 提出的 systolic architecture 通过规则 PE 网络在相邻单元之间传递数据，为矩阵乘和卷积计算提供了高复用的硬件组织方式~\cite{kung1982systolic}。Google TPU 使用大规模 systolic array 获得高吞吐推理性能~\cite{jouppi2017tpu}。Eyeriss 系列则从能量效率角度系统讨论了 row-stationary 数据流和层级存储复用~\cite{chen2016eyeriss,chen2019eyerissv2}。Sze 等人的综述对 DNN 加速器的数据流、存储层次和能效权衡进行了系统总结~\cite{sze2017efficient}。

在 FPGA 方向，Qiu 等人较早展示了在嵌入式 FPGA 上部署 CNN 的完整流程~\cite{qiu2016going}；Angel-Eye 进一步提出从模型到 FPGA 映射的设计流程~\cite{guo2019angeleye}；S2A 和 RTL compilation 相关工作关注从高层描述生成 systolic array 或模块化 RTL~\cite{wei2017s2a,ma2018rtlcompiler}。针对 YOLOv3-tiny 的轻量化 FPGA 加速器也已有报道~\cite{ding2022tinyyolo}。这些工作说明 FPGA 对 CNN 推理具有可行性，但许多研究更强调模型映射、阵列生成或单层性能，对真实链式推理中的 DMA 交互、IFM 打包、partial-PSUM 反馈和 pass 级调度开销讨论较少。

本文的工作不以绝对 FPS 领先为目标，而是以一个可复现的 MPSoC 端到端系统为载体，研究真实 YOLO 链式推理中的数据流和调度瓶颈。相比仅报告理论吞吐或单层仿真的工作，本文更强调硬件 RTL、Vitis runtime、外部 golden、板级 batch-chain 验证、DDR 图像输入和性能计数器之间的一致闭环。

\section{本文主要工作}

围绕上述问题，本文完成的主要工作如下。

\begin{enumerate}
    \item \textbf{设计并实现面向真实 YOLOv3-tiny 链式推理的卷积加速器架构。} 加速器基于 INT8 systolic array，支持 3x3 卷积、原生 1x1 卷积、INT32 partial-PSUM、逐通道重量化、activation LUT、2x2 maxpool 和 OFM 写回；系统接口采用 AXI-Lite 配置和四路 AXI-Stream/DMA 数据通路，能够与 A53 bare-metal runtime 协同执行 Conv0--Conv9。

    \item \textbf{提出面向真实层的数据流优化方法。} 针对频繁 DMA 启动和软件打包开销，本文实现 batch stream 与预打包权重布局；针对后端层 IFM 重排开销，设计 raw-HWC tile cache，使软件传输自然 HWC tile，由硬件按 K pass 和卷积窗口顺序重放；进一步通过 backend full-tile 调度减少 13x13 后端层的空间 tile 固定开销。

    \item \textbf{优化多 K pass 卷积中的 partial-PSUM 反馈和 pass 级调度。} 本文实现流水化 PSUM drain、early drain、continuous PSUM collector、partial-PSUM overlap 和 pass-level prefetch，使当前 pass 的计算、部分和写回、下一 pass 的权重/IFM 准备尽可能重叠，同时保持 AXI 数据格式和软件 ABI 稳定。

    \item \textbf{建立从 RTL 到 KV260 板级运行的验证和性能诊断体系。} 本文使用 Icarus Verilog、Vivado XSIM、外部 RTL golden、链式 semantic golden 和 Vitis board smoke 构成多层验证流程；在硬件中加入 stage、sub-stage、raw-HWC、prefetch、collector、pass timeline 等计数器，用于定位性能瓶颈和解释优化收益。
\end{enumerate}

\section{论文组织结构}

本文共分为六章。第一章介绍研究背景、相关研究现状和本文贡献。第二章给出卷积计算、INT8 量化、systolic array、YOLOv3-tiny 层结构和 MPSoC 平台基础。第三章介绍加速器系统架构，包括 PS/PL 协同、AXI 边界、systolic core、后处理流水线和 OFM 输出路径。第四章讨论数据流与分块调度优化，包括 K/COUT/spatial tiling、batch stream、预打包权重、raw-HWC cache 和 backend full-tile。第五章介绍 partial-PSUM 反馈、pass-level prefetch、系统集成和性能计数器。第六章给出正确性验证、板级端到端性能、消融实验、资源时序结果和局限性讨论。
